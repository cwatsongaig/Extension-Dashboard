## Context

The `UserBranches` table in the database maps users to their branch access. Currently the app matches `currentUser.branch` (a single name like "CINCINNATI") against the branches list to get one branch ID. Users like Jake Miller actually have access to CINCINNATI, INDIANAPOLIS, and SM CONTRACTORS PROG — but only see Cincinnati data.

The SQL endpoints already support comma-separated branch IDs (the `IN (@Branch)` pattern handles multi-value). We just need to fetch the user's actual branch list and pass all IDs.

## Implementation Steps

### Step 1: Add `/api/user-branches` endpoint in `api/main.py`
New endpoint that takes a `username` parameter and returns the user's branch IDs/codes/names from `UserBranches` joined with `Branches` and `Users`.

### Step 2: Create `user_branches.sql` query file
```sql
SELECT br.Id AS BranchId, br.Code AS BranchCode, br.Name AS BranchName, ub.IsPrimary
FROM UserBranches ub
INNER JOIN Users u ON ub.UserId = u.Id
INNER JOIN Branches br ON ub.BranchId = br.Id
WHERE u.UserName = @Username
ORDER BY ub.IsPrimary DESC, br.Name
```

### Step 3: Modify `loadDashboardData` in `app.js`
Change the signature from `loadDashboardData(branchId, branchCode)` to `loadDashboardData(branchIds, branchCodes)` where these are comma-separated strings of all the user's branches.

### Step 4: Update the initialization flow (DOMContentLoaded)
Instead of:
- Fetch `/api/branches` → match by name → get single ID

Do:
- Fetch `/api/user-branches?username=<currentUser.username>` → get all branch IDs and codes → pass comma-separated to `loadDashboardData`

### Step 5: Update `switchUser()` function
Same change — when switching users, fetch their branch list instead of matching a single branch name.

### Step 6: Update `handleEnvToggle()` function
Same pattern — use the user's branch list when re-fetching after environment switch.
